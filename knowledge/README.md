Это файлы с происхождением знания, статусами и историей Git, не автоматически подключённая память чата и не база эмбеддингов.

- [index.json](index.json) — перечень записей.
- `records/KN-*.json` — тезисы с источниками, узлами и вопросами проверки.
- [templates/entry.example.json](templates/entry.example.json) — шаблон, не реальный источник.
- [decisions/README.md](decisions/README.md) — решения.
- [Протокол эволюции](../docs/06-evolution.md) — история изменений.

## Current и legacy

По умолчанию `python3 scripts/context_pack.py` строит пакет из `model/research/matrix-20261114.json`. Он сохраняет текущие определения, источники и статусы 56 адресов. `--node P2` означает Голос; `--node P3.2.1` — Скелет / Нет / аспект да.

**Исторический knowledge-реестр не добавляется в current автоматически.** В старых карточках P2/P3 и пространственные стороны могут означать другое. Совпадения строки адреса недостаточно для переноса. Это ограничение защищает от смешения, но не означает, что старые знания исчезли или бесполезны. При необходимости прочитай конкретную карточку вручную, сохрани её исходную нумерацию и обоснуй применимость; не превращай её в current-норму.

Для аудита прежней модели:

```bash
python3 scripts/context_pack.py --layer legacy --node P3
python3 scripts/context_pack.py --layer legacy --node P3 --include-candidates
python3 scripts/context_pack.py --layer legacy --node P3.left --query "понимание" --format json
```

В legacy `P3` — исторический Голос. По умолчанию там включаются `adopted`; `--include-candidates` добавляет `captured` и `under_review` с их статусами. `--all-statuses` предназначен для аудита, включая `rejected` и `superseded`. `--query` — буквальный поиск, не embeddings. Читай сведения об исключённых записях; пустая выдача не доказывает отсутствия знаний.

## Добавление записи

Сохрани отдельный тезис с ID `KN-YYYYMMDD-NNN`, источником, действительно изученным фрагментом, датой и статусом `captured`. Укажи исходную схему адресации и область применимости в тексте карточки; не вводи несовместимые поля без обновления схемы и проверки. Обнови индекс, не повышай статус без решения. Заменённые определения сохраняй в истории и связывай с новым решением.

Для будущей автоматической current-выборки потребуется явная проверенная миграция адресов и статусов. Векторный индекс, если появится, будет дополнительным способом поиска, не источником истины.

Отдельное пространство связанных MD-понятий (контракт, якорь и другие) возможно как следующее расширение. Оно не является текущим реализованным реестром, не подменяет задачи/checkpoints и не меняет определения матрицы.

## Передача состояния

В новом запуске загрузи свежую версию пакета и checkpoint: задачу, решения, проверенные артефакты, незакрытые якоря, условия возврата. Источник и дата важнее уверенного пересказа. Доступ к файлам и их сохранение требуют реального механизма и разрешений.
